    \projectheading{小麦 AI 智能票务交易平台}{后端开发}{2026.06--2026.09}
    \begin{itemize}
        \item \textbf{项目架构}：面向演出票务的智能选票与高并发交易场景，基于 Spring Cloud、Nacos、Gateway、MyBatis-Plus、Redis、RabbitMQ 等构建微服务票务平台，覆盖演出检索、票档库存、订单创建、支付及超时取消等核心链路。
    
        \item \textbf{AI 智能购票能力}：面向传统购票平台筛选条件复杂、用户决策成本高的问题，设计自然语言购票入口，将用户对城市、时间、预算、演出类型及座位偏好的描述转化为结构化检索条件；通过票务服务接口获取实时演出与票档信息，为用户生成候选演出与购票建议，实现“自然语言需求 → 演出检索 → 票档推荐 → 下单”的智能购票链路。
    
        \item \textbf{缓存与热点访问优化}：针对首页、演出详情及票档余量等高频读取场景，使用 Caffeine 缓存首页热点数据、Redis 缓存演出详情与实时余量，并结合布隆过滤器及缓存重建机制降低无效查询与热点 Key 回源压力；演出详情接口耗时由 205ms 降至 132ms，吞吐量由 487 QPS 提升至 1493 QPS。
    
        \item \textbf{库存扣减与并发控制}：围绕“演出 + 票档”维度设计库存并发控制，早期采用 Redisson 分布式锁串行化库存修改，进一步使用 Redis + Lua 将库存校验与扣减合并为原子操作，减少锁竞争与网络交互，核心购票接口吞吐量由 68.2 QPS 提升至 88.5 QPS，并避免高并发场景下库存超卖。
    
        \item \textbf{订单可靠性与异常补偿}：基于 RabbitMQ 延迟消息实现订单超时关闭，围绕库存扣减、订单创建、支付结果等状态设计补偿流程；对重复/取消/失败及库存回滚等异常场景进行幂等控制与状态校验，降低异步交易链路中的数据不一致风险。
    \end{itemize}
