# JD Matching and Tailoring

Use this reference when the user provides a target job description, asks for ATS optimization, wants a tailored resume, or asks how well a resume matches a role.

## Inputs

Prefer three inputs:

- Master resume or raw career facts
- Target JD
- Candidate constraints: target city, seniority, language, page length, non-negotiable facts, and preferred role direction

If the JD is missing, ask for it or perform only a general resume review.

## Matching workflow

1. Parse the JD into a requirement map.
2. Separate hard requirements, preferred requirements, responsibilities, domain signals, seniority signals, and soft skills.
3. Extract evidence from the resume for each requirement.
4. Mark coverage as strong, partial, weak, or absent.
5. Reorder and rewrite resume content to surface the strongest true matches.
6. Identify gaps that need real experience, study, projects, or proof.
7. Produce tailored copy without inventing claims.

## Requirement map

Use a compact table:

`JD requirement | Importance | Resume evidence | Coverage | Action`

Importance:

- `must-have`: core technology, degree, location, years, or responsibility
- `preferred`: bonus skill or domain
- `signal`: wording that reveals what the employer cares about

Coverage:

- `strong`: direct evidence exists and can be strengthened
- `partial`: adjacent evidence exists but wording needs alignment
- `weak`: only a vague mention exists
- `absent`: no truthful evidence found

## Keyword handling

Use exact JD language only when true. Prefer natural integration into skills, project bullets, and experience entries.

Good keyword placement:

- Skill category headings
- First lines of role-relevant projects
- Responsibility bullets with evidence
- Summary or target role line when credible

Avoid:

- Dumping keywords in one long skills paragraph
- Repeating a keyword with no evidence
- Adding tools the candidate cannot discuss in an interview

## Match score

Use this rubric only when scoring against a specific JD. For a general quality review without a JD, use the rubric in `programmer-resume-guide.md` instead.

When scoring, use a transparent 100-point rubric:

- Must-have coverage: 35
- Responsibility alignment: 20
- Technical depth and evidence: 20
- Results/metrics/proof: 15
- Formatting and keyword discoverability: 10

Give a score range when the resume or JD is incomplete.

## Tailoring actions

Common actions:

- Reorder skills to match JD priority
- Move most relevant project/work item earlier
- Replace generic verbs with role-specific actions
- Add missing context from confirmed facts
- Remove unrelated content that dilutes the target direction
- Convert broad claims into concrete evidence
- Add a concise summary only if it improves first-screen clarity

## Gap recommendations

For absent but important requirements, do not fake. Recommend one of:

- Ask the candidate for overlooked real experience
- Build a small project demonstrating the skill
- Add a training/certification only if completed
- Leave it out and strengthen adjacent evidence

For programmer roles, useful gap-filling projects should be deployable, testable, and explainable. A project that is online, documented, and measurable is stronger than a local-only demo.
