写在前⾯

简历有多重要？

简历是⼀个⼈求职的⻔⾯，也是整个求职过程中的 第⼀步 。如果简历不过关的话，后⾯的笔试、⾯试可能连机会都没

不断发掘并改进⾃⼰的不⾜、经过了多个版本的持续优化后才凝练⽽成的。

在你学完基础的开发技能，⽐如开发框架（前端 Vue、后端 SpringBoot 等），并且能够独⽴运⽤所学技术来完成⼀个

是帮助⾃⼰对当前的状态和学习进度、不⾜有个清醒的认识。

正所谓有积累，才能锋芒毕露。

如果你现在不想准备简历也没关系。很多公司会在 8 ⽉份正式开启秋招（提前批），所以⼤家在 6 - 7 ⽉份的时候准备

好简历就没问题；很多⼤⼚会在 2 - 3 ⽉份开启春招（提前批），所以⼤家参加春招的话尽量在 2 ⽉份准备好简历。

答：简历最好⼀⻚指的是 “少⼀些废话，⽤⼼凝炼内容”，证⾯试官有耐⼼看下去，⽽不是强制⼀⻚。 只是希望⼤家

在简历上突出重点、惜字如⾦，⽽不是像记流⽔账⼀样什么都写。如果你能写的内容就是很多的（⽐如冲击⼤⼚、⼯

作 3 年以上、求职等级较⾼），那么⼀⻚纸以上完全没问题。

头能吸引住⼈，⽤户可能就点赞三连了；如果开头是废话，⽤户直接划⾛，哪怕后⾯是⼲货可能也看不到了。

MonacoEditor 实现

2. xxx
3. xxx

基本建议

所以，⼀定要保证简历上的每个词都要 准确，不能产⽣歧义 。另外，尽量减少⼝语化的内容，不说⽤ xx 技术做了

1、整体

1.1 简历篇幅过⻓

建议：⼀般校招简历以 ⼀⻚纸 为最佳，保证⾯试官有耐⼼看下去。但注意，并不是说强制⼀⻚纸，只是希望⼤家在简

历上突出重点、惜字如⾦，⽽不是像记流⽔账⼀样什么都写。如果你能写的内容就是很多的（⽐如冲击⼤⼚、⼯作 3

年以上、求职等级较⾼），那么⼀⻚纸以上完全没问题。

1.2 简历缺少 XX 板块

建议：⼀份完整的程序员简历包含个⼈信息、教育背景、专业技能、荣誉奖项、⼯作经历、项⽬经历、科研经历、校

园经历、个⼈优势等内容。

其中，个⼈信息、教育背景、专业技能、项⽬经历是 必须具备 的！

1.3 简历篇幅不够合理

建议：合理分配各部分内容占⽤的篇幅，推荐的占⽐如下：

个⼈信息 5 ~ 10%

教育背景 10 ~ 15%

专业技能 20 ~ 30%

项⽬经历 30 ~ 40%（⼯作 / 校园 / 科研等经历也算在内），对绝⼤多数同学来说，这部分是 核⼼ ！

其他内容 0 ~ 20%（⽐如奖项、个⼈优势等）

总之，尽量多写经历来体现⾃⼰的实践能⼒、解决问题的能⼒，少写⼀些正确的废话（⾃我评价）。

1.4 简历模板不够整洁

建议：⼀份优秀的简历必须在 外观和内容 上都很出⾊，做到秀外慧中。所以，挑选⼀个好的简历模板是⾄关重要的！

简历的板块划分要清晰、排版要整洁、内容不要太挤或太空；⾊调不宜过暗或过亮，推荐蓝⾊或淡灰⾊；⾊彩不要太

丰富，要让⼈看起来舒服。可以尝试⻥⽪⾃⼰⽤过的、⾮常精简整⻬的免费简历模板：

https://www.laoyujianli.com/template/1685547340318179330

当然也可以尝试其他模板，只要保证简历的整体结构是从上到下、布局清晰、排版整⻬、简洁⼲净就好，拒绝花⾥胡

哨的⾊块和图标。

1.5 简历⽂件命名或格式不规范

建议：简历⽂件的命名虽然没有绝对的规范，但是要 仔细查看岗位描述 是否有⽂件名规则的要求。

注意！除公司特别要求之外，⽂件格式⼀定要⽤ PDF！！千万不要⽤ Word！！！因为使⽤ Word 可能会因为打开软件

的版本不同⽽出现预期之外的排版错乱，这个影响是致命的。

1.6 简历中出现错别字

建议：整个简历中千万不要有错别字！尤其是技术名词或者专业术语。否则会给⼈感觉⾮常不认真，竞争激烈时搞不

好直接就挂了。

所以写完简历后，⼀定要⾃⼰通读⾄少 3 遍，保证⾏⽂通顺、且⽆任何错别字！

1.7 简历没有明确的重点或求职⽅向

建议：整个简历⼀定要有⼀个明确的、和求职岗位匹配的⽅向。

我认识⼀些学的技术⽐较多的同学，他们可能⼜会 Python ⼜会 Java ⼜会前端，写到简历上的项⽬也是各⽅向的都

有，然后⼜没有在简历的开头注明 “求职意向”，就导致⾯试官完全不知道他要找哪个⽅向的⼯作。

并不是说会的技术、写简历上的技术太多了不好，⽽是要有⼀个侧重点。⽐如找 Java 岗位的⼯作就把 Java 项⽬放最

上⾯，⽤更多的篇幅去介绍。也建议⼤家找⼯作前越早明确⽅向越好，不要到最后什么都只学了⼀点，反⽽平平⽆奇

了。

当然，如果你⾃⼰在多个⽅向学得都不错，可以准备多份不同的定制化简历，并根据不同的岗位、公司和岗位描述来

调整优化简历（⽐如增加部分细节、调换内容的顺序等）。

⽐如你前后端都会，投递后端开发岗位时，把后端技术放在前端技术上⾯去写，项⽬经历、实习经历等都要侧重于后

端。

1.8 技术名词⼤⼩写错误

建议：技术名词最好严格控制⼤⼩写，⽐如数据库技术写 “MySQL” ⽽不是 “mysql”，从微⼩的细节中体现你的专

业性。

1.9 ⽤词不专业或不凝练

建议：简历上的每⼀个词汇，都能够反映出你的⽔平。

很多同学的简历⽤词⽐较随意，⽐如 “我⽤ axios 库完成了对数据库的查询”。

其实⼤家都⼼知肚明，axios 是⼀个前端请求库，可以和后台进⾏交互，实现对数据的查询和管理。

但上⾯那个表达，语⾔不够清晰和凝练，还可能会给⾯试官⼀种感觉：你真的知道 axios 是什么？你真的和后端联调

过么？

所以，⼀定要保证简历上的每个词都要 准确，不能产⽣歧义 。另外，尽量减少⼝语化的内容，不说⽤ xx 技术做了

xx，⽽是⽤（基于） xx 技术实现了 xx。

1.10 内容重复

建议：简历中（尤其是项⽬和⼯作描述中）尽量不要出现重复的内容，不仅占⽤了空间，还会让⾯试官感到疲惫。1.11 简历内容过于简单

建议：当你简历上没有什么可写的内容、⼜必须要尽快投递简历时，可以 适当包装 。

注意，此处的包装不是指改变⾃⼰的学习、⼯作年限等（这种属于 “隐瞒和欺骗”，⼀般不建议这么做），⽽是指适当

夸⼤。

毕竟写简历的本质就是：如何以⼀种吹⽜⽪的⽅式尽量表现出你的能⼒。

虽然写简历要真实，但不能太⽼实！尤其是对于没有⼯作经历、项⽬经历、荣誉奖项的同学，要学会适当包装、合理

包装。

⽐如尝试将你⽬前正在学的技术从 “了解” 改为 “熟悉”，或者把你还没来得及实现的项⽬功能先提前写上去等等。

但是，不要过分包装，⽽且既然你提前把⼀些内容写到了简历上，就要加倍努⼒赶紧去真正学会 / 实现它。

1.12 简历内容很多，但没有突出重点

建议：在写简历时，可以将部分内容⽚段进⾏加粗，或者多去写某部分的内容，来吸引⾯试官去提问。

⽐如：

1. ⾃⼰掌握的很好技术名词
2. ⾃⼰项⽬中⼤量运⽤的技术
3. ⾃⼰项⽬的优化成果数据
4. 获得的名词较⾼、含⾦量较⾼的奖项
5. 其他同学很少接触到的新技术或深⼊知识点

1.13 部分语句不通顺

建议：你写在简历上的每⼀句话都有可能会暴露你的思维逻辑能⼒，所以必须保证语句通顺、逻辑合理。

1.14 简历空间没有合理利⽤

建议：除⾮你实在写不满⼀⻚纸，否则简历上的所有内容都要做到 “惜字如⾦”。能只⽤⼀⾏写完的内容，就不要换第

⼆⾏再加那么⼏个字。另外，简历上尽量不要出现空⽩，⽐如⼀⾏只写了半句话、或者只占⽤了半⻚纸等。

实在不知道写什么，就去参考下别⼈的简历，并且⾃⼰再多学习⼀些技术、做⼀些项⽬。

1.15 简历各板块的顺序不合理

建议：根据个⼈优势对各板块进⾏排序，把最有亮点的部分放上⾯。⽐如你的奖项⽐较多、但学历相对低了⼀些，就

可以把奖项写在前⾯、学历放到最后去写。

2、个⼈信息

2.1 个⼈信息占⽤的篇幅过多

建议：⼀般个⼈信息只占⽤简历整体 5 ~ 10% 的篇幅即可。可以通过在⼀⾏内同时写多个信息来节约空间，并保证间

距合理。

2.2 照⽚不清晰 / 不端正

建议：照⽚要清晰端正，蓝底 / ⽩底 / 红底都可以，最好表情⾃然、⾯带微笑，尽量穿⽩衬衫或者正装，体现⼀个⼈的

精神⾯貌。

2.3 写了固定的期望薪资范围

建议：除⾮公司明确要求，否则不建议写期望薪资。原因如下：1. 很多公司的薪资还算公开透明，没必要写

2. 可能你⾃⼰本⾝对某个⾏业的薪酬⽔平不了解，薪资写⾼了可能会错失求职机会
3. 当你的表现或实际⽔平超出了你写的预期薪资范围时，会被⼈按照你的预期薪资来砍价，相当于把⾃⼰限制

住了

当然，如果你要应聘⾼级岗位、或者对⾃⼰很⾃信，那么可以写⽐较⾼的期望薪资，从⽽过滤⼀些公司、猎头的打

扰。

2.4 缺少个⼈相关链接

建议：因为简历的篇幅和内容有限，所以如果你的个⼈经历很丰富，推荐在简历上补充⼀些链接，⽐如个⼈⽹站、个

⼈博客、个⼈作品集、代码仓库等，体现你的实践能⼒。

3、教育背景

3.1 成绩排名⼀般

建议：⼀般排名⾼于前 20% 的同学才建议在简历上写排名，否则没有优势。（尖⼦班除外）

3.2 主修课程浪费了空间

建议：本⾝就是计算机相关专业（或者专业和求职岗位相匹配）的同学不⽤再占⽤空间去写⾃⼰的主修课程了，因为

学校教的内容往往⽐较基础、⽽且⾯试官默认这个专业或者投递这个岗位的同学都应该会这些课，写上去也没有什么

优势。

但是建议⾮计算机相关专业（或者专业和求职岗位不匹配）的同学适当列举关键主修课程，优先列举和求职岗位相关

的、取得分数较⾼的课。

如果有得分较⾼的课程（⽐如 90 分以上），可以在课程名后⽤括号补充分数。

3.3 存在学历造假⻛险

建议：除⾮迫不得已，否则不建议学历造假，因为⼤多数公司都是有背景调查的，哪怕通过造假顺利⼊职，也可能会

被突然查出来并强制离职。

4、技术栈

4.1 同⼀⾏列举了过多的技术名词

建议：写你会的技术栈时，尽量不要⽤特别⻓的⼀句话、像报菜名似的列举过多技术名词。建议采⽤列表的形式，每

⼀⾏单独写⼀个技术的多个⼦知识点或者⼀系列相关的技术，做到把每⼀块技术写得更具体、清晰。

4.2 XX 技术写得过于简略，没有充分利⽤空间

建议：⼀般情况下，你掌握或熟悉的技术不要只写⼀个技术名词，⽽是建议利⽤好每⼀⾏的空间，多补充该技术中你

掌握的知识点和技术细节，会让⼈觉得更真实、有说服⼒。

当然，如果某个技术你只是了解或听说过，就把你知道的知识点写上去即可。

4.3 同⼀⾏列举了多个不相关的技术

建议：从简历的技术栈部分中不仅可以看出你学过哪些技术、掌握哪些技术，还可以看出你对技术的分类和知识点的

梳理能⼒。尽量每⼀⾏写清楚⼀个技术，或者把⼀系列相关的技术放在同⼀⾏（⽐如 SSM 框架）；⽽不要把前端、后

端、算法等知识点混在同⼀⾏去写。

4.4 缺少你对 XX 技术的实践应⽤能⼒

建议：技术栈部分光写⾃⼰会什么技术、了解哪些知识是不够的，因为⼤多数⾯试官重视的是你的实践能⼒，即你能

不能使⽤该技术完成⼯作，⽽不是纸上谈兵。因此可以适当补充半句：“你能⽤这些技术做什么？”，从⽽体现你的实践能⼒。公司往往倾向于选择问题解决能⼒强、实践经验丰富的同学。

4.5 XX 内容过于基础，⽆法体现出你的能⼒

建议：尽量避免去写默认所有⼈都会的内容，⽐如 Java 的⼏种数据结构、前端 HTML 的标签、⾯向对象编程等。

4.6 XX 内容写得过于宽泛和模糊，缺乏可信度

建议：尽量不要写过于宽泛、模糊不清、⽆法证明的的内容，⽐如：

熟悉⾯向对象编程

有⼀定后端基础

了解常⻅性能优化⼿段

有良好的开发规范

具备良好的编码能⼒

专业的⾯试官基本就默认当做你不了解、或者不具备这些能⼒。

你应当把这些宽泛的知识具体化，⽐如：

熟悉⾯向对象编程 => 了解哪些软件开发原则、熟悉哪些设计模式等？

有⼀定后端基础 => 你学过哪些后端知识？

了解常⻅性能优化⼿段 => 具体了解或实践过哪些性能优化⼿段？

有良好的开发规范 => 熟悉或使⽤过哪些开发规范、⽤过什么⼯具来规范团队开发？

具备良好的编码能⼒ => 会⽤哪些开发⼯具、熟悉哪些编程技巧？

写得更具体⼀些，才会更有说服⼒。

4.7 各技术点的顺序不当

建议：和做短视频⼀样，我们要尽量把最吸引⼈的部分放在简历的最上⾯。所以建议优先把岗位描述中明确要求的、

你学得最好的技术放在前⾯去写，和求职岗位关系没那么⼤的、仅是了解的知识点放到最后作为补充。

4.8 技术栈和其他同学过于相似，缺少区分度

建议：哪怕⼤家都写同⼀个技术，你也可以写更多、更深⼊的知识点。

建议多阅读借鉴他⼈简历的技术栈部分，查漏补缺。

此外，平时除了学习主流技术外，最好能多去技术社区阅读⼀些技术⽂章，扩展⾃⼰的知识⾯。

5、荣誉奖项

5.1 未重点突出⾼级别、⾼含⾦量的奖项

建议：获得奖项的级别或含⾦量很⾼时，建议把奖项级别加粗来吸引⾯试官，⽐如 XX 竞赛全国 ⼀等奖 。

5.2 奖项未排序

建议：优先把认可度⾼的、参赛范围⼴的、获奖级别⾼的、和求职岗位更相关的奖项放上⾯，⼀些不知名的竞赛放到

6、⼯作经历（实习经历）

6.1 ⼯作描述过于简单
